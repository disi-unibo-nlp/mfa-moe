# Clean R3-E B4 feature-method amendment — 2026-10-02

This version extends `R3E_RESOURCE_AND_METHODS_AMENDMENT_v0.1.md` for B4 feature construction. The user's instruction to use all needed GPU hours and submit all needed analyses also authorizes the necessary CPU work. Historical protocols and results remain separately versioned. The clean B1 result and the independently priced R3-D work are unchanged.

The clean B4 primary uses the exact-ID-clean development/tuning GPT A population frozen by `R3E_CLEAN_PREFLIGHT_v1.json`: 509 attempts, 496 duplicate families, five repeats, five outer folds and three inner folds (100 training sets). All B1 deltas and class-conditioned marginal profiles are fitted on the corresponding training set. Outcomes are not read at feature-freeze time.

The clean lexical adjustment is `PAlex = PA - E[PA | token ID, absolute-position bin]`. For each training set, ten pseudo-class draws use the empirical class distribution of that set's training tokens within the exact token-ID and position stratum. A missing exact stratum falls back to the training position bin; if absent, it falls back to the entire training set. For training rows the pseudo labels are within-stratum permutations of training labels. The real in-fold B1 delta scores each pseudo-label draw. The reference construction sees token IDs and positions of scored rows but never their class labels or outcomes. Seeds are fixed in the source at `20260930`, with fold index and draw index. The `PAlexB` column is a compatibility alias in the clean feature file and must not be interpreted as an independent sensitivity.

This is a prospective version of the lexical-adjustment estimand, corresponding to the historical reading-B scoring rule with an explicitly training-fold-only reference. The historical reading A refitted B1 on ten class shuffles drawn over the whole historical token universe. It is a retrospective/transductive sensitivity, with a different estimator and population; do not call the clean version an exact replication of historical reading A. The clean outcome-CV primary uses the prospective `PAlex`, not a held-out-informed transform.

The B4 feature construction has a maximum **32.5 CPU core-hours**: a two-CPU, 15-minute one-pair/one-shuffle outcome-blind smoke stage (0.5 core-hour), then a 16-CPU, two-hour full 43-pair/ten-draw stage (32 core-hours). The smoke must pass and produce source/fold-bound outputs before full submission. These are ceilings, not claimed expenditure.
