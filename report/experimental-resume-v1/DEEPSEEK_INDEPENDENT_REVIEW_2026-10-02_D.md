## Audit verdict

The packet shows unusually careful sealing, native-duplication and exposure-matched controls (strengths), but the executed evidence cannot yet answer the stated objective. What exists is a 13-family, 256-token, single-binary-rating micro-screen selected post hoc on "high agreement"; the packet contains no graded final answers, no ordered multi-step trajectory outcome, and one generation/rating pair that cannot run because its contract schemas differ. Treat all "trajectory", "accuracy", and "token-cost" claims as unestablished on this packet.

## Proven findings, ranked

**A1 (Critical, proven). The artifacts measure at most one binary step in a 256-token window, not ordered class trajectories.**
The registration asks for ordered transitions with a 1,024-token local endpoint (`PROTOCOL_v0.1.md` 0116–0117, 0141–0144). The executed screen fixes `max_tokens=256` and a single slot `[0]` (`run_eligible_micro_serial_v2.py` 0078–0079, 0160–0161), and the rubric explicitly defers the 1,024-token endpoint to "a separately frozen continuation study" (`CAUSAL_ELIGIBLE_IMMEDIATE_SEMANTIC_RUBRIC_v1.md` 0032–0035). `trajectory_completion` (ordered, two-step capable) has no caller anywhere in the packet. Concretely, a two-pulse template's second action lives at positions [512,768) under the registered slots (`design.py` 0193, 0205–0206) — the current horizon cannot even reach it. Consequence: no ordered-sequence, dwell, re-entry, loop, or reversal-order estimand is estimable from this evidence. Check: run the frozen 1,024-token continuation with dense labels and call `trajectory_completion` before any trajectory language is used.

**A2 (Critical, proven integration bug). The deactivation run's rating stage cannot start with the supplied artifacts.**
`CAUSAL_ELIGIBLE_DEACTIVATION_BLIND_RATING_PRICE_v3.json` declares schema `routing-eligible-deactivation-blind-rating-price-v3` (line 0002), but the rating driver requires `eligible-immediate-blind-rating-price-v1` and `status == 'PASS_COMPLETE_STAGE'` (`rate_eligible_immediate_semantics_v1.py` 0082–0092). The v3 price's status is `RESOURCE_PRICE_BEFORE_GENERATION; BLIND_FRAME_AND_RATING_DRIVER_REQUIRE_POSTGENERATION_HASH_BINDING` (line 0023). Shape check: the driver's price fields (`frame_sha256`, `frame_file_sha256`, `driver_sha256`, `assigned_requests`, `ratings`, `max_decode_tokens`) do not exist in the v3 price object (0002–0025), so `validate` fails on the first predicate. Check: emit a post-generation price v4 whose schema the driver actually validates; run `--cpu-preflight` before any GPU allocation.

**A3 (High, proven protocol violation / causal ambiguity). "Control of trajectories" is being tested with necessity (deactivation) interventions.**
The main-arm design does test positive bias +0.5/+1.0 (`run_eligible_micro_serial_v2.py` 0102–0107; dictionary 0023–0026, 0096–0099), but the v3 run is negative bias −1 and force-off (`run_eligible_deactivation_serial_v3.py` 0105–0111). Deactivation arms answer "is this expert necessary?", not "can routing be steered to a different trajectory" — the two-arm objective ("causally change") needs both directions reported separately. Also, `Operator("bias", -1, 1.0)` applies a −1 logit shift (`spec.py` 0400–0401); at top-k=8 over 256 experts this may leave the expert selected (it is not force-off), so "deactivation" naming is a hypothesis the dose telemetry must test. Check: report actual membership_changes/turnover per arm; label v3 explicitly as a necessity diagnostic, not trajectory control.

**A4 (High, proven defect in the deployed detector). The live gate runs the older suffix window and a malformed display-math regex.**
`live_gate_v1.py` 0016 imports `transitions_v2` (v2.1), so the corrected containment test `start <= item.start and item.end <= end` in `transitions_v22.py` 0119–0121 is not used operationally; v2.1 instead uses a ±4-character proximity window (`transitions_v2.py` 0119–0121), which can promote truncated candidates to evidence. Additionally, `_MATH` is `\\\[(.{1,240}?)\\\)` (`transitions_v2.py` 0020–0021; same in `transitions_v22.py` 0019–0020), a mismatched bracket pair, so `\[...\]` display math is never captured, while the count check never notices (only `\(`/`\)` and `\[`/`\]` counts are compared, 0051–0052). `_closed_math` also returns `None` (total abstention) on any brace imbalance (0053–0054), suppressing even `\boxed{}` detection in `classify_sentence_v2` (0071). Check: version-bind the live detector, fix the regex to `\\\[(.{1,240}?)\\\]`, and re-run the detector fixture confusion matrix.

**A5 (High, proven selection bias). The 13-family screen is post-hoc selected on high agreement, breaking the registered 48-family discovery plan.**
`run_eligible_micro_serial_v2.py` builds rows from a `JOINT_QWEN_NATIVE_EXACT_POOL` and requires exactly 13 globally disjoint families (0032–0047), and the price admits "Discovery maximum support is 13 globally distinct families, below the registered 48-family maximum; this is a labeled small causal screen, not validation" (`CAUSAL_ELIGIBLE_MICRO_SERIAL_PRICE_v2.json` 0022). The family pool was chosen from records already agreeing with detector/raters. This conditions the treatment effect on detector agreement and plausibly selects easy prefixes; it also departs from "full enrollment order fixed before behavioral selection, no replacements" (`PROTOCOL_v0.1.md` 0028–0031). Check: publish the eligibility funnel (all detector positives, which failed labeling/prefix constraints, and their native outcomes) or, better, re-enroll the registered discovery order and treat 13-family results as a pilot.

**A6 (High for the stated objective, proven). Token cost and accuracy are underspecified or missing.**
The protocol requires recording emitted and injected tokens (`PROTOCOL_v0.1.md` 0151–0152) and measuring accuracy (0008–0009). `paired_itt` reduces cost to a single `tokens` scalar (analysis.py 0141–0142, 0152–0153, 0167) with no injection ledger merge; `live_gate_v1.py` 0101–0127 collects side-query tokens into a separate ledger that may never be recorded in the aligned artifacts. No answer-extraction or gold-grading code appears in the packet — the blind frame stores only a 256-token continuation text and one binary rating (`build_eligible_micro_blind_frame_v2.py` 0148–0170). Check: freeze an answer parser/grader and a cost schema (prefill, emitted, injected) before the utility scout; report them jointly with uncertainty as the protocol requires (0166–0169).

**A7 (High, proven hypothesis gap). One of the three registered hypotheses has no exercised path.**
`TRANSITIONS` includes `failed_check_to_revise` (`design.py` 0013; `PROTOCOL_v0.1.md` 0039–0046), but the action dictionary contains only `candidate_to_verify` and `approach_to_commit` target templates (0001–0151), and both executed screens restrict to two transitions (`run_eligible_micro_serial_v2.py` 0023; `run_eligible_deactivation_serial_v3.py` 0023). This is consistent with "unsupported hypotheses are omitted" (protocol 0045–0046) but must be reported as a non-confirmatory omission, not a studied transition.

**A8 (High, proven construct-validity risk). The rater is told the transition being tested, so it is not naive to the hypothesis.**
The blind frame allowlist includes `transition` (`build_eligible_micro_blind_frame_v2.py` 0189–0190), and the rating prompt embeds the type-specific rule keyed on that field (`rate_eligible_immediate_semantics_v1.py` 0097–0112). This is arm-blind but not hypothesis-blind: the instruction "True only if…" primes each hypothesis. Check: at minimum compute reader agreement separately per transition and audit prompt sensitivity with a paraphrased rubric; ideally rate with the hypothesis inferred from the frozen prefix, not supplied.

**A9 (Medium, proven). Random-control identity varies between seeds and arms without documented blocking.**
`random_set_by_family_seed` selects `[seed]` (`run_eligible_micro_serial_v2.py` 0155), so family f's random arm uses a different expert set at seed 0 vs seed 1; family-level balance of set usage holds (0123–0127), but the paired random estimand is not frozen per question across seeds. This inflates across-seed contrast variance in the random arm and complicates the reversed comparison. Check: use a single frozen random set per family, rotate sets across families only, and record the realized assignment in ARM_MAP (already partly done).

**A10 (Medium, proven comparability gap). Native and order arms are compared under `enforce_eager=True, max_num_seqs=1` (serial), while native performance/accuracy claims would be reported in that low-throughput mode.**
`run_eligible_micro_serial_v2.py` 0022, 0028–0029. The protocol allows a discovery reference to differ, but any utility comparison using the utility scout must be run in the same engine profile or the timing/cost axis is confounded. Check: state the profile in every result table; do not mix serial micro-screen semantics with utility-scout costs.

**A11 (Medium, proven fragility). Manifest validation can pass a control schedule that differs from the base driver's assignment logic.**
`run_eligible_micro_serial_v2.py` checks only that `random_set_by_family_seed` is balanced (0108–0117), not that it matches the rotation `(i + j) % n_sets` (`design.py` 0175–0180), so a manifest could bind a different balanced schedule and the base driver would silently use it. Check: recompute the schedule in the validator and require equality.

**A12 (Low/medium, proven). Seals and code bindings are strong but not uniformly complete.**
`run_boundary_micro_screen.py` requires exact overlay/qualification hashes and code digests (0064–0085), which is a real strength. However, `ordered_vllm.py` reports `'ordered-worker-v1'` (0020) while `worker_adapter.py` installs `ordered-worker-v2` (0017), and the driver never asserts the reported version equals the manifest's; `manifest['actions']` is not tied to the action-dictionary hash in `run_boundary_micro_screen.validate_manifest`. Check: assert worker version equality and dictionary binding at preflight.

## Hypotheses (not proven on this packet)

- **H1.** The −1 bias leaves target experts selected often enough that v3 "deactivation" is weak; the `force_off` arm is the real removal test. Testable with the existing `ordered_action_dose`/`membership_changes` telemetry (`worker_adapter.py` 0147–0160).
- **H2.** The `approach_to_commit` proxy (Explore→Plan/Implement) and the single-expert replacement (dictionary 0351) may be too weak to produce separable effects; the dictionary itself flags the proxy weakness.
- **H3.** `paired_itt`'s bootstrap may be conservative (family cluster with question weighting) and could report a `DEGENERATE_BOOTSTRAP` for binary endpoints with 13 families; expected precision — not demonstrable from summaries alone (`analysis.py` 0184–0186).
- **H4.** The rating cap `MAX_TOKENS=1024` with `enable_thinking=True` can silently consume the answer budget inside an unterminated think block, making `parse_rating` return `None` and biasing ITT if unrated responses correlate with arm (0124–0132, 0208–0215).

## Shortest credible route to a defensible result

1. Repair or replace the deactivation rating price/contract and run the rating driver's CPU preflight (A2).
2. Run the frozen 1,024-token continuation for both transitions with dense seven-class labels and `trajectory_completion`, on the 13-family screen first (replication/order/pilot) and on the registered 128-family mechanism pool if feasible; this is the only path to ordered-trajectory claims (A1).
3. For the mechanism run, use a positive/negative bias pair and a proper force-off arm against native and duplicate-native, with pre-registered matched random sets (A3, A9, A11).
4. Freeze an accuracy grader and a full cost schema (prefill + emitted + injected) and run the utility scout in the same engine profile as the reference (A6, A10).
5. If resources are short, the defensible null is: "under this engine and detector, at this dose and horizon, no ordered trajectory change was detectable; power was X." Do not upgrade it to trajectory "control" without step 2.

## Bottom line

The codebase is audit-friendly and several controls (native duplication, exposure-matched random sets, sealing, arm-blind frames) are genuine strengths. But as supplied, the packet cannot answer the objective for ordered reasoning-class trajectories, and the accuracy/token-cost axes are not yet implemented end-to-end; the v3 rating pipeline is additionally blocked by a schema mismatch. The highest-value fixes are the 1,024-token dense-label trajectory run, the accuracy/cost schema, the positive+negative intervention pair, and repairing the detector/price contracts — in that order.
