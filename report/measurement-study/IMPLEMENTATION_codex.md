## T2 review fixes (2026-09-25)

- **B1 outcomes schema/pointer** (`campaign_v3_plan.read_outcomes`): reads `outcomes_v3.latest.json` (or an explicit sidecar + manifest), verifies pointer/sidecar/manifest hashes, filters `corpus=='card-v3'` and the model before validating, accepts nullable `Int64` columns, accepts every documented `adjudication_status` (including `capped`) and any termination string (null -> `unknown`), keys rows by `(corpus, model, dataset, problem_id, sample_id)` and rejects duplicates. The real 32529-row historical sidecar and the real test cohorts are exercised by `test_campaign_v3_plan.py::test_real_cohort_and_real_outcome_contract`.
- **B2 cohort binding** (`load_cohort_manifest`/`validate_cohort_binding`): capture binds the cohort file sha256 plus the manifest's own `manifest_sha256`, which is recomputed from the core fields written by `sample_cohorts.write()`. The removed `outcome_sidecar_sha256` field is never read.
- **B3 inclusion probability**: cohort A requires `0 < p <= 1`; cohort B requires exactly `null` (paired case-control selection carries no population weight).
- **B4 outcomes out of capture**: capture manifests, validation bindings, capture results and packets contain no outcome field at all; the validation binding digests only `spec + code_binding + cohort_binding + maximum_input_tokens`, so cohorts A and B share one verify receipt. `production_analyze` takes `--outcomes` (sidecar or pointer), joins at analysis time and fails closed if a planned attempt has no sidecar row or the sidecar trace identity/tokens/termination disagree with the capture manifest.
- **M1 analysis bundle**: `production_analyze` no longer requires the capture manifest `code_binding` to equal the analysis bundle hash. The capture code binding is recorded as `capture_code_binding` provenance (artifact hashes and the capture gate already established it); analysis runs from its own frozen bundle.
- **M2 differential**: `capture_buffers.compare_hf_vllm_capture` reports per-layer statistics and gates on zero flips where the reference selection gap is `>= eps` and a near-tie (`gap < eps`) flip rate `<= 1e-3`, plus a per-layer effective-weight relative-L2 bound (`<= 5e-3`). Exact expert-set equality is required only when both sides declare identical kernels.
- **m1 shard sizing**: production shards use a fitted runtime `startup + per_attempt + seconds_per_token * tokens`. The fit comes from `--verification-receipt` (the two measured verification traces), or from explicit measured values; a negative fitted intercept clamps to zero with a conservative rate instead of inventing a negative fixed cost.
- **m2 verify walltime/drain**: verify-only planning requires at least 5 h, and the capture job drains with a measured margin (the larger of 15 min and the measured cost of the attempt that would start, plus 300 s write-out).
- **m3 bundle closure**: the frozen bundle now also carries `src/moe_exp/routing_study/*.json`, the `moe_margin_guiding` and `moe_identity_guiding` packages, `pyproject.toml` and `sbatch/routing_study_smoke.sbatch`, i.e. every path returned by `src/moe_exp/routing_study/common.py:code_hashes()`. `test_bundle_v3.py` freezes the real worktree and asserts the frozen bundle reproduces the live `code_hashes()`.
- **m4 duplicate attempts**: the cohort manifest's union is planned as one row per attempt id, so `--cohort all` (after the label gate) captures each attempt once and both cohorts reference the same packet. The approved DAG plans B before labels and A after, so the intersection is captured twice with different cohort variants; the measured extra cost (`shared_attempts`, `duplicated_completion_tokens`) is recorded in every `ready.json` under `dedup`. With the current real cohort the intersection is 0 attempts, so the duplicate cost of the approved order is 0 tokens for the test cohort.
