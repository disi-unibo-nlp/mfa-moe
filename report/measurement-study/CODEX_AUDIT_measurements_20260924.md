## Other correctness-critical findings

1. **Stale primary analysis resume bypasses input hash (confirmed bug).** `measurement_study/production_analyze.py:20` returns any existing complete.json before reading/hash-checking the input. Although :22 writes input_sha256, it is never compared on resume. Reproduced with the exact AST function and stub metrics module: a marker with input_sha256=old-input and a new input returned the old marker, recomputed=false. Frozen `production-code-recovery-v12/measurement_study/production_analyze.py` has the same lines. A corrected-score rerun into existing output would retain old associations. Require new versioned output roots and explicit input/scorer/code hash checking before reuse.
2. **Primary analysis escapes the frozen scripts path.** `production_analyze.py:18,34` prepends live `ROOT/scripts` when importing analyze_available_metrics, including frozen v12. The launcher cd's to bundle, but this explicit path overrides its script snapshot. Main does not validate imported script hashes. Corrected implementation must import/hash the frozen helpers so a bundle SHA describes code actually run; preserve old results as historical until exact imports are recorded.
3. **All-unknown annotations become numerical zero class fractions.** `scripts/analyze_available_metrics.py:148–153` computes counts from labeled sentences and divides each class count by max(1,n). When n=0 it produces seven zeros, making missing annotation look like genuine class absence. Supplement class_token_fraction (`production_supplement.py:26–29`) correctly omits fractions when no observed token mass. Fix CPU compact construction to emit unavailable for all-unknown classes, preserving coverage denominators.
4. **Retrospective judge labels contain future context.** `annotation_partition.py:76` includes next_sentence. These labels can train/evaluate a prefix-based surrogate, but their class semantics and demonstrated sentence-level F1 do not establish deployable causal online state recognition. A controller needs prefix-only evaluation, grouped unseen questions and a forward-only segmentation/trigger rule. This is a design limitation, not corruption of existing labels.
5. **No outcome overlay or scoring acceptance is checked in current report completeness.** `production_report.py:28–45,91–103` validates capture coverage/bindings, and :155 can set full_requested_model_coverage from stage completion. A complete computational pipeline can therefore report full coverage with invalid outcomes. Add separate outcome-validity and scientific-design gates; model-stage completion alone cannot mean paper ready.
