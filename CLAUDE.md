This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

paper built from it. The host is CINECA LEONARDO. The account and cluster rules in
`/leonardo_work/IscrC_MIOSR/lmolfett/AGENTS.md` apply to everything here:
- write only to the allowed locations;
- no GPU work on login nodes;
- use Slurm only after the user authorizes the workload and the budget;
- no commit or push without approval.

## Layout

- **`scripts/`:** bash only. One folder per topic, one short launcher per experiment, and a README in each folder.
- **`src/`:** Python only. One package per topic directly under `src/` (there is no `moe_exp` wrapper), run as `python -m <topic>.<module>`.
- **`tests/<topic>/`:** the tests for each topic.
- **The experiment table:** the root `README.md` maps every paper experiment to its launcher, module, receipt, and paper table or figure.

## Environments and tests

The repo `.venv` is empty; do not use it. The environments live in `/leonardo_work/IscrC_MIOSR/lmolfett/mfa-moe/envs/`:

- **`correlation-client-3.11`:** pydantic, numpy, pandas, pytest. It has no torch, scipy or dspy. Use it for light tests on the login node.
- **`vllm-cu129`:** vLLM 0.29 plus torch cu129. It is used by every job (`scripts/slurm/env.sh` puts it on PATH). Its imports are slow on the login node.
- **The DSPy env:** the judge client and GEPA use it. Its path is `$DSPY` in `scripts/slurm/env.sh`.

The package is not installed. Always set `PYTHONPATH=src`.

```bash
E=/leonardo_work/IscrC_MIOSR/lmolfett/mfa-moe/envs/correlation-client-3.11/bin/python
PYTHONPATH=src PYTHONDONTWRITEBYTECODE=1 $E -m pytest -q -p no:cacheprovider tests/test_imports.py tests/labeling
```

- **Login node:** only light tests (600 s CPU limit).
- **Full suite:** run it in a CPU job with vllm-cu129, with the DSPy site-packages on PYTHONPATH, `STUDY_DATA_ROOT` pointing at the main checkout's `report/final-routing-20261015-r1`, and `TMPDIR` on WORK. Fixtures reject `/tmp`.
- **`tests/test_imports.py`:** checks statically that every import, `python -m` string and module-alias attribute resolves, and that every module is reachable from an entry point.
- **Lint:** ruff, line length 100, py311. Ruff is not installed on the host.

## Cross-cutting contracts

- **Router semantics differ by family:**
  - Qwen3.5/3.6 and Gemma expose probabilities, stored as log-probs.
  - Qwen3 and GPT-OSS expose logits.
  - GLM and Nemotron use sigmoid affinities with selection-correction biases.

  Always use the model's actually selected experts (`models/router_adapters.py`), so boundary gaps can be negative.
- **`labeling/spans.py` is the single source of truth** for sentence segmentation, trace digests and offset alignment. Labels and views key off `trace_digest` plus sentence spans, so a change there invalidates existing annotations.
- **Releases are source-bound.**
  - `python -m steering.release` (through `scripts/steering/whole.sh`) seals a release: it snapshots the committed tree into `mfa-moe/releases/<commit>` and writes `report/NAME/RELEASE.json`.
  - Jobs run from that snapshot, never from the working tree.
  - A correction is a new revision folder that names its predecessor.
  - Never edit or overwrite an older revision, a seal or a historical receipt. Failed jobs stay recorded and charged.
- **Frozen files:** some files are bound by hash to pre-registrations or published receipts. They include `routing/efficiency_link_prereg.py` (sha256 31de9c46…) and `routing/lexical_data/make_readme.py`. Never edit them.
- **Unknowns stay unknown.** Truncated, censored, incompatible or unread outcomes are kept as unknown in the bounds. They are never dropped, redrawn or relabelled, and gates are never relaxed after the fact.
- **Reasoning length** comes from the server's `reasoning_tokens`, falling back to counting via `token_replay` offsets. vLLM reports 0 for gpt-oss.
- **Slurm jobs:**
  - They source `scripts/slurm/env.sh`, which loads the modules, works offline (`HF_HUB_OFFLINE=1`), and puts every cache, `TMPDIR` and `VLLM_RPC_BASE_PATH` in the short per-job folder `mfa-moe/r/<jobid>`. That folder exists because of the 107-character Unix socket limit.
  - It also sets a per-job `PORT` and `URL`, so two 2-GPU jobs on one node don't collide, plus `TIKTOKEN_ENCODINGS_BASE` for gpt-oss.
  - Strip `SLURM_*` before calling `sbatch` from inside a job (`env -u SLURM_JOB_ID sbatch ...`).
  - Process pools need one BLAS thread (the default). Single-process fits ask for more with `--export=ALL,THREADS=4`.
- **Outputs** go to `results/` and `data/labels/` (both gitignored), `report/<campaign>/`, and the FAST scratch roots named in the code. Published trace roots and label sets are provenance; never overwrite them. Analyses that can be rerun take a new `--out` folder.
- **Commits** are authored as LorMolf only. Never add a Claude co-author line.
