paper built from it. The host is CINECA LEONARDO; the account/cluster rules in

## Architecture

The work has two layers. The upstream pipeline produced the traces, labels and router captures.
Later campaigns consume those outputs for the eight-model routing study and its interventions.

### Upstream pipeline

- `gepaLLMAsJudge/`: GEPA/DSPy optimization of the prompt that labels reasoning sentences with
  the seven Schoenfeld episode classes. Its frozen program JSON
  (`results/gepaLLMAsJudge/qwen3.8-27b-medium-final-s42-v3/selected_program_*.json`) is the
  judge used everywhere downstream.
- `correlation_pipeline/`: generation, sampling, annotation, forward replay, analysis, dynamics
  (stages below).
- `probeTest/`: layer-wise hidden-state probes; its `best_by_target` layers define the default
  layer subset retained by forward extraction.
- `moe_guiding/`: exploratory vLLM plugin (`vllm.general_plugins` entry point) that alters top-2
  routing at inference time.
- Shared: `schemas.py` (`TraceRecord` is the unit record passed between every stage), `models/`
  (loading, per-family router adapters, streaming extraction), `datasets/loaders.py`.
  `old/` and `src/moe_exp/old/` are archived experiments.

Correlation pipeline stages:

1. **Generate** (`generate.py`, `benchmarks.py`, `scoring.py`): vLLM OpenAI server, six default
   math benchmarks, 32,768-token completion budget. Saves exact prompt/completion token IDs, a
   tokenizer fingerprint and character offsets (`metadata.token_replay`). Per-model server
   settings (reasoning parser, MTP, context) are in `model_profiles.py`.
2. **Sample** (`sample_stratified.py`): 100k sentence units per source model, one completion per
   `source_problem_id`, stratified by dataset x correctness x reasoning-length quartile, split
   into four 25k parts. Deterministic and plan-hashed; a different plan into an existing
   directory is refused.
3. **Annotate** (`annotation_batch.py`, `batch_judge.py`, `batch_predictor.py`, `annotate.py`):
   the Qwen3.8-27B judge labels sentences in batches with checkpoint resume.
   `annotation_merge.py` / `labels_export.py` verify the parts and publish merged labels.
4. **Forward replay** (`extract.py` -> `models/routing_extraction.py`,
   `models/router_adapters.py`): teacher-forces the saved token IDs through the HF checkpoint and
   never re-renders chat templates. Streaming hooks reduce router/hidden tensors to compact
   per-trace features; only top-k expert IDs persist unless `--save-raw-tensors` is passed.
5. **Analyze** (`analyze.py`, `features.py`, `expert_analysis.py`, `views.py`,
   `view_analysis.py`): correctness/episode associations with problem-clustered bootstrap.
   Repeated attempts are never independent; length-truncated generations are excluded.
6. **Dynamics** (`dynamics/`): class transitions, trailing-window routing overlap/entropy/JSD,
   sentence-level expert counts. Enabled in extraction with
   `--dynamics --all-router-layers --router-only`.

`spans.py` is the single source of truth for sentence segmentation, trace digests and offset
alignment. Labels, views and dynamics key off `trace_digest` plus sentence spans, so a change
there invalidates existing annotations.

### Eight-model routing study (current work)

`configs/final_routing.yaml` freezes the design: models `gpt, nemotron, qwen35, qwen36, gemma,
glm, qwen330b, lfm25`, the seven classes, seeds, folds and budget ceilings. Compact results go to
`report/final-routing-20261015-r1/`; bulk data goes to the FAST scratch root named there.

`src/moe_exp/study/` is the maintained implementation. It imports frozen design, endpoint and
scheduler helpers from `final_routing/` and `research_campaign_v3_r6/` rather than copying them.
It has three entry points:

- **Journaled job graph**: `scripts/study/run.sh plan|status|submit|resume|export` (wraps
  `python -m moe_exp.study`). `plan` is read-only. `submit` and `resume` reconcile the same
  submission journal. `submit --replace-terminal` applies only after an authorized correction
  with a source-matched release receipt.
- **Reduced driver** (`moe_exp.study.driver`), which produced the completed results: 2-GPU jobs
  via `scripts/study/driver.sh`, sharded by question family and submitted with
  `scripts/study/submit_production.sh SHARDS HOURS MODEL...`. `scripts/study/ledger.sh` tallies
  `fr-*` jobs against the 6,000 billing-hour cap. CPU analyses run through
  `scripts/study/cpu.sh MODULE ARGS`. The final effects receipt is
  `report/final-routing-20261015-r1/driver/analysis-final/EFFECTS.json`.
- **Causal rescue**: `python -m moe_exp.study.rescue COMMAND --cohort .../COHORT.json`
  (`cohort`, `engineering-plan`, `submit --stage ...`, `status`, `reader-admit`, `analyze`, ...)
  and `moe_exp.study.rescue_reader`, with stage wrappers in `scripts/slurm/rescue_*.sbatch`.
  The stage order (validate, engineering, generate, prepare, pilot, reader-admit, waves,
  analysis) is in `src/moe_exp/study/README.md`.

## Cross-cutting contracts

- **Router semantics differ by family.** Qwen3.5/3.6 and Gemma expose probabilities (stored as
  log-probs). Qwen3 and GPT-OSS expose logits. GLM and Nemotron use sigmoid affinities with
  selection-correction biases. Always use the model's actual selected experts rather than raw
  top-k (see `router_adapters.py`), so boundary gaps can be negative.
- **Releases are source-bound.** Each campaign release records its source commit, Python closure,
  wrappers, inputs and runtime in `SOURCE.json`/`BINDING.json`. Jobs run from that snapshot or
  archive, not from the working tree. A correction becomes a new revision directory
  (`report/<campaign>-rN+1/`) that names its predecessor. Never edit or overwrite an older
  revision, a seal, a journal or a historical receipt. Failed jobs stay recorded and charged.
- **Checkpoints and invalidation.** Pipeline stages resume from checkpoints keyed by content
  hashes (traces, program, judge settings, replay/router-capture versions, feature schema,
  code). If you change semantics, bump the relevant version so stale outputs are recomputed or
  refused. `provenance.code_provenance()` hashes all of `src/moe_exp/**/*.py`, so any source
  edit invalidates CPU-gate files that GPU jobs check.
- **Unknowns stay unknown.** Truncated, censored, incompatible or unread outcomes are kept as
  unknown in the bounds. They are never dropped, redrawn or relabelled, and gates are never
  relaxed after the fact.
- **Reasoning length** comes from server `reasoning_tokens`, falling back to counting via
  `token_replay` offsets. vLLM reports 0 for gpt-oss.
- **Slurm wrappers** refuse to run without `SLURM_JOB_ID`, `module load python/3.11.7
  cuda/12.6`, run offline (`HF_HUB_OFFLINE=1`) and redirect every cache into a per-job directory.
  For vLLM with tensor parallelism, keep `TMPDIR` and `VLLM_RPC_BASE_PATH` short
  (`/leonardo_work/IscrC_MIOSR/lmolfett/mfa-moe/r/<jobid>`) because of the 107-byte Unix socket
  limit. Strip `SLURM_*` before calling `sbatch` from inside a job (`env -u SLURM_JOB_ID
  sbatch ...`). gpt-oss needs
  `TIKTOKEN_ENCODINGS_BASE=/leonardo_work/IscrC_MIOSR/lmolfett/mfa-moe/cache/tiktoken`.
- **Outputs** go to `results/`, `data/labels/` (gitignored), `report/<campaign>/` and the scratch
  paths named in the wrappers. Published trace roots and label sets are provenance; never
  overwrite them.
