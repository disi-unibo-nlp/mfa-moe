# scripts/generation

Generate benchmark traces with a model, and check answers with the judge. The two GPU jobs start their own server; the list of answers to check is built on the CPU.

| Script | What it does |
| --- | --- |
| `generate_answers.sbatch HF_MODEL DATASET SHARD NSHARDS OUT_DIR` | Starts the server of `HF_MODEL` (`start_server` in `scripts/slurm/env.sh`, which runs `scripts/serve/serve_model.sh`) and generates one slice of one benchmark: every attempt whose position in the list of attempts is `SHARD` modulo `NSHARDS`. 2 GPUs, 20 hours. No new request starts in the last 3 hours, so running ones can finish. |
| `list_rejected_answers.sh TRACES_DIR ITEMS_JSONL` | CPU job. Lists the answers that finished (were not cut at the token cap) but that `math_verify` rejected, one item per answer, from the traces in `TRACES_DIR`. The model is read from the traces. `ITEMS_JSONL` must not exist yet. |
| `judge_answers.sbatch ITEMS_JSONL VERDICTS_JSONL` | Starts the judge (`start_server $JUDGE_MODEL`) and decides whether each listed answer equals the reference answer (three votes per item). 2 GPUs, 6 hours. A rerun skips the items already in `VERDICTS_JSONL`, whose folder is created if needed. |

```bash
# the first and the second half of GPT-OSS on AIME 2024
OUT=/leonardo_work/IscrC_MIOSR/lmolfett/mfa-moe/repo/results/correlation_pipeline/card-v3/gpt/generation
sbatch scripts/generation/generate_answers.sbatch openai/gpt-oss-20b aime24 0 2 $OUT
sbatch scripts/generation/generate_answers.sbatch openai/gpt-oss-20b aime24 1 2 $OUT
```

`HF_MODEL` is the Hugging Face id of one of the seven models (`python -m models.roster --captured` lists them). `DATASET` is one of `math500 aime24 aime25 olympiad amc23 minerva` (`gpqa_diamond` and `mmlu_pro` also exist but are not part of the paper). LFM2.5 is generated by `steering.lfm25_generation native` (see `scripts/steering`).

- Output: `OUT_DIR/<served model>/<dataset>/` (for the paper, `OUT_DIR` is `.../repo/results/correlation_pipeline/card-v3/MODEL/generation` in the main checkout, which git ignores). Each finished attempt is one file in `generation_shards/`, so a job that stops (or hits the deadline) is resumed by submitting the same command again.
- When all shards of a dataset are done, collect them into `traces.jsonl` and `manifest.json`. This needs no server:
  `sbatch -J assemble scripts/slurm/run_module_cpu.sbatch generation.generate_answers --model openai/gpt-oss-20b --datasets aime24 --assemble-only --output-dir $OUT`
  Every run also records its datasets in `OUT_DIR/<served model>/summary.json`; assembling one dataset at a time adds to the entries already there.
- `list_rejected_answers.sh` reads the folder that holds `<dataset>/traces.jsonl`, e.g. `$OUT/openai--gpt-oss-20b`. The module and the sampling settings are described in [`src/generation`](../../src/generation/README.md).

Paper use: the traces feed every other experiment; the accuracies and the J1 verdicts fill the benchmark tables.
